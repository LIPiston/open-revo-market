## 1. 双通道解耦（Skill §0.2）

**Skill 原文**：主题皮肤通道 `active_skin` → `<style id="openrevo-theme-skin">`；背景壁纸通道
`active_background` → `<style id="openrevo-custom-background">`；两者**完全正交解耦，可同时生效、任意组合**。

**判定：✅ 属实（实测坐实）**

| 断言 | 实测证据 |
|---|---|
| `openrevo-theme-skin` 注入 id 存在 | 0.8.8 前端 JS 命中 **6** 次 |
| `openrevo-custom-background` 注入 id 存在 | 同上 **4** 次 |
| 旧 id `openrevo-custom-skin` 仍被兼容读取 | 同上 **2** 次（启动路径回退） |
| 两个 IPC 都存在 | exe 明文 `…load_plugin_html set_active_background backgroundId load_plugin_background_css set_active_skin skinId load_plugin_theme_css …`（@6984239，`src\system\webview_orchestrator.rs`） |
| 两个状态独立、各有自己的 setter | JS 里 `if(j.plugin_type==="skin"){…enabled:N.id===T…}` 与 `if(j.plugin_type==="background"){…enabled:N.id===T…}` 是两个并列分支，各自持有独立选中态 |
| `data-background` 属性真的挂上 | JS 根容器 `"data-background":S||void 0`；`documentElement` 上 `S?P.setAttribute("data-background",S):P.removeAttribute("data-background")` |
| 旧版（0.8.7）确实没有 | `_extracted\bundle.partial.js`（584,148 B）里 `openrevo-custom-background` / `openrevo-theme-skin` / `set_active_background` / `plugin_type==="background"` **全 0 命中** |

## 2. 「零 Base64 原生支持」（Skill §0.3）

**Skill 原文**：宿主 Rust 后端读插件 CSS 时，**会自动把 `url('assets/bg.png')` 等相对路径在内存中解析并转成
Data URI 注入**；**严禁**写脚本把图片编码成 base64，直接写正常相对路径即可。

**判定：⚠️ 机制成立、但表述不准 —— 分两半看**

| 一半 | 判定 | 证据 |
|---|---|---|
| 宿主会**自己**把图片 base64 化 | **✅ 属实** | exe 里的固定模板常量：`e/* Auto-generated by OpenRevo Background Engine */` + `.openrevo-shell {` / `background-image: url("data:` + `;base64,` + `") !important;` / `background-size: cover !important;` / `background-position: center !important;` / `background-repeat: no-repeat !important;` / `}`，`.mini-drawer-root {` 同样四行（@7780400 起逐字） |
| 宿主会**改写作者手写的相对 `url()`** | **❌ 无证据** | 全 exe 只有 **10** 处 `url(`：4 处随机机器码 / 旧词典（@3750251、@3751792、@6569740、@6632806 附近的网页词典）、2 处 `background:url(` / `background-image: url(`（同样是词典字符串 @6671154、@6689868）、4 处全在 Background Engine 模板（@7780240、@7780299、@7780492、@7780703）。**没有任何一处是「读作者 CSS → 找 url() → 替换」的代码痕迹**；`;base64,` 全 exe 仅 **3** 处，也全在 Engine 模板里 |
| 顺手证伪的附带项 | — | `"assets/` 只有 5 处、全是前端自己的 blob 路径表（`/assets/index-Tu8RPoda.js`、`/assets/index-D5aBypuh.css`、图片资源等）；tarball 解析侧的 `resolve`/`join`/`normalize` 是 `plugin:path\|…` 的权限串，与 CSS 无关 |

**对文档的写法**：作者手写 CSS 里的相对 `url("assets/x.jpg")` **能不能取到图，本仓库未验证**；
已确证的是**宿主自己编码图片文件**这条路径（§3）。⇒ 本仓库既有的「图片内联 base64 `data:` URI」
做法**继续有效、不是多余**；Skill 的「严禁 base64」说法**不宜照抄**。

## 3. Background Engine（Skill §3 `image` 字段 + §6 方式 B）

**Skill 原文**：manifest 声明 `"image": "assets/wallpaper.jpg"` 即可零代码铺满；方式 B 是「目录里只放
`manifest.json` + `wallpaper.jpg`」。

**判定：⚠️ 机制 ✅ 属实，`image` 键名 ❌ 不成立**

| 项 | 结论 | 证据 |
|---|---|---|
| 零代码壁纸机制存在 | ✅ | 上面的固定模板常量（宿主自己生成 `.openrevo-shell` + `.mini-drawer-root` 两段铺满样式） |
| MIME 靠扩展名表 | ✅ | `font/otf` `font/ttf` `font/woff` `font/woff2` `image/svg+xml` `image/gif` `image/webp` `image/png` `image/jpeg` |
| **图片是被「探测」而不是被 `image` 键指认** | ❌ Skill 写法不成立 | exe **按 12 个固定文件名挨个试**（大小写不敏感）：`background.jpg` `background.jpeg` `background.png` `background.webp` `wallpaper.jpg` `wallpaper.jpeg` `wallpaper.png` `wallpaper.webp` `bg.jpg` `bg.jpeg` `bg.png` `bg.webp`（@6999097）。`"image"` 在 exe **0 处**、在前端 JS 仅 2 处且都是 React DOM 的 `case"img":case"image"` 事件分支；manifest 字段表（@6949111）里也**没有** `image` |
| 错误串佐证探测语义 | ✅ | `Neither background CSS ('` + 占位 + `' / 'theme.css') nor image asset found in plugin '` + 占位 + `'` |

**所以方式 B 的正确写法是**：目录里放**那 12 个文件名之一**的图片 + 只声明 `plugin_type:"background"`；
不需要（也不存在）`image` 字段。

**`background_css` 的默认值**：`background.css` 字面量在 exe **0 命中**（`theme.css` 有 3 处），
说明默认文件名**不是硬编码串** —— 「manifest 给什么读什么，缺省回退 `theme.css`」，与 Skill §3 的
「默认读取 `background.css`（回退读取 `theme.css`）」**回退部分 ✅、（如果没给字段就）默认部分 ⚠️ 未证实**。

## 4. 调试流程（Skill §7）—— 推翻 Skill 自己的说法

**Skill 原文**：「免重启热刷新：点【刷新】按钮，宿主调用 `invoke('get_custom_plugins')` **立即重新扫描并挂载新插件**」。

**判定：✅ 成立（0.8.8-dbfe615 起，Skill 这一条是对的）—— 本页第一版曾判 ❌，已按新构建反转。**

新构建（`v0.8.8-dbfe615`）的刷新按钮 handler 逐字：

```js
j = async (S = !1) => {
  b(!0);
  try {
    const D = await m("get_custom_plugins") || [];
    u(D),
    S && (i && a && (D.some(W => W.id === i) ? a(i) : a(null)),
          o && d && (D.some(W => W.id === o) ? d(o) : d(null))),
    p && p()
  } catch (P) { console.error("Failed to load custom plugins:", P) } finally { b(!1) }
}
```

绑在 `{onClick:()=>j(!0), className:"toggle-btn", title:"刷新已安装插件列表并热重载当前样式"}` —— 传入的 `!0`
即形参 `S`，于是**重扫列表之后**，会拿当前 `activeSkin`(`i`)／`activeBackground`(`o`) 去重跑
`onApplySkin`(`a`)／`onApplyBackground`(`d`)，也就是重新 `load_plugin_theme_css` /
`load_plugin_background_css` 并刷新 `<style>.textContent`；插件若已从新列表消失则把 active 置 `null`
（连带移除 `<style>`）。

旧构建（`v0.8.8-bf72755`）逐字对照，**没有 `S` 形参、没有回调重放**：

```js
k = async () => { _(!0); try { const j = await m("get_custom_plugins"); d(j || []) } catch … },
```

title 也只是 `"刷新已安装的插件列表"`。⇒ **这不是「之前查错了」，而是开发者在新构建里补上了热重载**。

**对本仓库的实操口径（取代旧版）**：改 `theme.css` / background CSS **只需点一次【刷新】**，
不必拨开关、也不必重启；装**新插件目录**同样「刷新」一步到位（旧版需要「刷新 + 拨开关」两步）。
原先那条「装完必须重启宿主」的结论只在 **0.8.7** 与 `bf72755` 之前成立。

### 9.3 新增 `data-form-factor` 与 Dev Mode 形态模拟（对插件无用）

两个根元素都加了 `data-form-factor`（值 `"gaming"` / `"thin_light"`）：

```jsx
// App 根
<div className="openrevo-app-root" data-theme={I} data-skin={b||void 0}
     data-background={k||void 0} data-window-mode={e?"full":"mini"}
     data-form-factor={(f?.form_factor)||"gaming"}>
// 主窗
<div className="acrylic-container openrevo-shell" data-slot="shell"
     data-theme={t} data-form-factor={(ie?.form_factor)||"gaming"}>
```

**它不挂 `documentElement`** —— 逐字 `const M=document.documentElement; b?M.setAttribute("data-skin",b):…,
k?M.setAttribute("data-background",k):…, M.setAttribute("data-theme",I),
M.setAttribute("data-window-mode",e?"full":"mini")` 里没有 `form-factor`。
且 `data-form-factor` 在 CSS 里 **0 引用**，新增的 6 个 `.sys-card*` 类在 CSS 里也 **0 引用**
（只在 JSX 里用）。⇒ 皮肤/背景插件**无法也无需**针对它写样式。

配套的 `--debug` 专属卡片（标题「机型形态与能力实时预览 (Dev Mode)」）在三个预设间切换
`real` / `thin_light` / `gaming`，纯前端伪造 `capabilities` 对象（`preview_xingyao_14` /
`preview_gaming`）。这是**宿主开发者自测模具裁切**用的，不是插件 API。

### 9.4 唯一实质行为变化 = §4 的【刷新】热重载
