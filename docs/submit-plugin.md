# 上架指南：把自己的插件放进市场

> **给谁看 / 什么时候读**：你是插件作者，想让插件出现在 OpenRevo 市场的列表里，或者想知道自己为什么还没进「已审核」时读这份。全文不需要你懂市场内部实现。
>
> 审核的判据、以及审核者那边要过哪些项，见 [`review.md`](review.md)。宿主能力的边界（什么行为在这套宿主上做得到）见 [`host-contract.md`](host-contract.md)。

## 三分钟版

```bash
# 1. 仓库里放好 manifest.json（见下一节）
# 2. 打上 topic —— 这一步就是「提交」
gh repo edit --add-topic openrevo-plugin
```

大约一小时后，你的插件会出现在市场里，标注为**未审核**。作者打上 topic 就已经完成上架，**不需要提 PR，也不需要改任何本仓库的文件**。

想进「已审核」分区，另外提一个 issue 申请（见「怎么申请审核」）。

## 写 `manifest.json`

放在**仓库根目录**，或放在任意一个**一级子目录**里（monorepo 会自动扫一层，见下文）。字段：

### 必填

| 字段 | 说明 |
|---|---|
| `id` | 插件的目录名。**安装后就叫这个名字**，要求全局唯一，只用小写字母、数字、`-` |
| `name` | 显示名，可以中文 |
| `version` | 版本号，建议三段数字 `1.2.0` |
| `plugin_type` | 八种形态之一，见下表 |
| `description` | 一句话说清**做什么**。不要写「最好的插件」这类无法核对的话 |

`plugin_type` 的八个取值：

| 取值 | 是什么 |
|---|---|
| `skin` | 主窗皮肤 |
| `background` | 背景壁纸 |
| `tab` | 顶栏页签（面板插槽） |
| `widget` | 桌面挂件 |
| `slot` | 微插槽，嵌进宿主既有页面 |
| `service` | 无头后台服务 |
| `shell` | 完整外壳 |
| `driver` | 硬件驱动 |

**写错取值不会报错，你会被静默归成 `tab`。** 校验器接受这八个值；其余值会被爬虫改成 `tab` 并在目录里记下原始值。所以填之前对照上表。

### 可选

| 字段 | 说明 |
|---|---|
| `entry` | 入口 HTML，通常是 `index.html` |
| `target_slot` / `slot_height` | 只有 `slot` 形态有意义；**已审核的 `slot` 插件必须写 `target_slot`**，否则装上也看不见 |
| `min_host_version` | 最低宿主版本，只接受三段数字 `0.9.4`。`>=0.9.4`、`^0.9`、`v0.9.4` 这类写法一律被丢弃（当没填） |
| `permissions` | 权限声明。**宿主不读它做任何拦截**，它只是给用户看的自述 |
| `telemetry` | 遥测声明。同为自述 |
| `service` | 伴随服务的配置（`executable` / `args` / `elevated` / `auto_start` / `auto_stop` / `port` / `health_url` / `description`） |
| `window` | 窗口几何：`width` / `height` / `resizable` / `decorations` / `transparent` / `always_on_top` / `skip_taskbar`。**`tab` 插件也读它** —— 不写的话「独立视窗运行」会用宿主默认的 240×320 **且没有标题栏，用户关不掉**。见下面「一定要写 `window`」 |
| `shortcuts` / `watchers` | 快捷键与监听规则，元素需带 `id` |
| `theme_css` / `background_css` / `image` | 皮肤、背景、图片资源 |

别写 `author` 字段期待它生效 —— 目录里的作者**一律取仓库归属者**（owner 登录名），`manifest` 里的 `author` 不入目录。这么做是因为自填的作者名与仓库控制权无关。

### 目录放哪都行

- 仓库根放 `manifest.json` → 整仓就是一个插件；
- 某个一级子目录里放 → 那个子目录是一个插件，一层扫不到就再深也扫不到。

一个仓库里有多个插件时，每个一级子目录放一份 `manifest.json` 即可。

### 一定要写 `window`

`tab` 插件（以及 `widget`）都可以被用户「独立视窗运行」弹出成单独窗口。没写 `window` 时宿主用默认的 **240×320、无边框**，表现是：窗口又小又挤，而且**没有关闭按钮** —— 用户只能去任务栏结束宿主进程。

```json
"window": {
  "width": 1120, "height": 780,
  "resizable": true, "decorations": true,
  "transparent": false, "always_on_top": false, "skip_taskbar": false
}
```

- `decorations: true` 是「关得掉」的**唯一**来源；
- `skip_taskbar: false` 让它在 Alt+Tab 里找得到；
- 布局要能自适应宽度，因为 `resizable: true` 之后用户会自己拖 —— 用 container query 而不是只写视口 `@media`（面板里的宽度不等于视口宽度）。

### 产物可以多文件，但单文件最保险

宿主把插件的 HTML 注入 iframe。**0.9.5 实测**：iframe 的基准 URL 是**你的插件目录**，所以相对引用能正常加载 ——

- `<link rel="stylesheet" href="style.css">` ✅
- `<script src="app.js"></script>` ✅
- `<img src="assets/logo.png">` ✅（子目录也行）
- `fetch('./manifest.json')` ✅

取证方法见 [`host-contract.md`](host-contract.md) §实测：外部资源。**但**这条只在 0.9.5 上验过，更早的宿主未必如此。所以：

- 只想兼容当前宿主 → 拆成 HTML / CSS / JS 三件，更好维护；
- 想兼容尽量多的宿主 → 全部内联进 `index.html`，最保险。

别用绝对路径（`/style.css`）或依赖宿主域名的 URL —— 那两种在沙盒里都取不到。

### 页面里不能用 `confirm` / `alert`

`tab` 形态的 iframe 没有 `allow-modals`，`window.confirm` 会被**静默拦掉并返回 `false`**。表现是「点了没反应、控制台零报错」。需要确认弹窗就自己画一个页面内的。

## 多久被收录

爬虫每小时跑一次（整点后第 17 分钟）。抓的是 GitHub 上带 `openrevo-plugin` topic 的仓库。

- **第一次收录**：打完 topic 后约一小时，最长一小时多一点；
- **之后的更新**：同样每小时跟进 `version`、`description`、`stars` 等字段；
- **想立刻看到**：市场页签每次打开都会自动查一次 GitHub，不用等爬虫 —— 但那只影响你自己看到的列表，别人还是要等下一轮。

爬虫只读仓库的默认分支。

## 怎么申请审核

打 topic 是**零审核**快车道：任何人打上 topic 就会出现在市场里，标注未审核。这让收录没有门槛，代价是「已审核」得单独申请。

申请方式：**在本仓库提一个 issue**，写上你的仓库地址（`owner/repo`，多插件仓库要带子目录）。不用改任何文件。

你会收到三种结果之一：

| 结果 | 你会看到 |
|---|---|
| 进「已审核」 | 市场里你的条目去掉未审核标记 |
| 收录，但仍标未审核 | 市场里保持原样；缺少的那几项写在仓库的覆写层里，issue 里会告诉你是哪一条 |
| 不予收录 | 从目录移除，理由写在拒绝说明里 |

理由会以文本形式留档在仓库里（不在市场界面上显示），所以你能看到具体缺哪一项，而不是只收到一句「没过」。

## 审查看什么

审核只关心两件事：**装上之后会不会在别人的机器上出问题**，和**它拿到的权限会不会害到用户**。

底层原因很直接：OpenRevo 运行在系统最高权限，插件做的事就是最高权限在做的事。所以「一个插件能读什么、能写什么」不是抽象风险。

### 会一票否决的四种情况

- 要提权、装驱动、或带伴随服务，**却没在 README 与清单里写明它做什么、为什么必须提权**；
- 读凭据/密钥**同时**能联网，且没有说明数据去哪；
- 运行期下载并执行代码，或用 `cmd` / `powershell` 拼字符串执行外部命令；
- 代码被混淆/打包成无法阅读，或仓库里没有与产物对应的源码。

这四条的共同点：**用户没法自己核实**。不是「看起来危险」，而是「装了就只能信作者」。

联网、读写文件这类风险不在此列 —— 它们会被如实列进披露，由用户自己判断。

### 会不会在别人机器上出问题

四项，缺一项就进不了「已审核」（但不会因此被下架）：

- **操作系统与架构**：支持 Win10 还是 Win11、x64 还是 ARM64、要不要 VC++ 运行库；
- **硬件厂商**：Intel / AMD / 两者。只支持一种的，请在 README 第一屏写清；
- **外部依赖**：驱动、PawnIO、其他软件、端口占用。**缺了会怎样要写出来** —— 是报错，还是静默失效；
- **`min_host_version`**：如实填三段数字。

第三条是审核者最在意的：用户以为装上了、其实没生效，比装不上更糟。

## 被拒之后

不必重开一个新仓库，也不用删掉重打 topic。改完缺的那几项，在同一个 issue 里说一声就会重新看一遍。

审核者不会因为代码风格、目录结构、README 排版拒绝你 —— 那不在判据里。

## 更新与下架

**更新**：推一个新 commit 就行。爬虫下一轮会更新 `version`、`description`、`stars` 与 `commit`。审核状态**不会**因为更新就自动失效，但如果你在更新里新增了提权、联网、执行外部命令这类能力，最好在 issue 里说明一句 —— 审核状态是人工给的，不是自动续的。

**下架（你自己想撤）**：删掉 topic，下一轮爬虫就不会再收录它。已经装了插件的用户的本地副本不受影响。

**下架（审核者判定）**：从目录移除，已安装的用户不受影响 —— 市场不远程删用户机器上的文件。

## 常见被拒原因

按实际发生频率排：

1. **提权/驱动没说明**。清单里写了 `elevated: true`，README 里却没有一句为什么要提权、读者该不该信任它；
2. **静默失效**。缺驱动时不报错、也不说明，用户以为生效了；
3. **只支持一种硬件但没写**。AMD 专用插件在 Intel 机器上装着、什么都没发生；
4. **源码对不上产物**。仓库里只有打包后的 `index.html`，或者源码被压缩过；
5. **联网 + 读凭据**，且没有说明数据去向。
